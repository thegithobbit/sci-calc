# SciCalc — науковий калькулятор із символьним диференціюванням

Лабораторна робота №3, варіант 7.

## Мета роботи

Розробити застосунок для платформи Android мовою Kotlin, що виконує наукові обчислення та має графічний інтерфейс. Окрім обчислення числових виразів, застосунок знаходить похідні функцій однієї змінної в символьному (аналітичному) вигляді. У роботі також застосовано засоби логування та інтернаціоналізації, доступні під час розробки Android-застосунків.

## Функціональність

Застосунок складається з двох екранів.

Екран калькулятора обчислює вирази, які містять арифметичні операції, піднесення до степеня, факторіал, тригонометричні та обернені тригонометричні функції, натуральний і десятковий логарифми, квадратний корінь, а також константи π і e. Аргументи тригонометричних функцій задаються в градусах або радіанах. Пріоритет і асоціативність операцій відповідають прийнятим у математиці: унарний мінус має нижчий пріоритет, ніж піднесення до степеня (−2² = −4), а піднесення до степеня є правоасоціативним (2^3^2 = 2^9). Допускається неявне множення, наприклад `2π` або `3sin(30)`.

Екран похідної знаходить похідну функції f(x) першого, другого або третього порядку. Результат подається формулою, яку можна знову використати як вхідну функцію. Якщо задано точку x₀, застосунок також обчислює значення похідної в цій точці та порівнює його з наближеним значенням, отриманим методом скінченних різниць.

## Архітектура

Обчислювальне ядро (пакет `core`) написане на чистому Kotlin і не залежить від Android SDK. Завдяки цьому його можна тестувати звичайними модульними тестами на JVM. Обробка виразу проходить такі етапи:

1. лексичний аналіз (`Lexer`): вхідний рядок розбивається на лексеми;
2. синтаксичний аналіз (`Parser`): методом рекурсивного спуску будується абстрактне синтаксичне дерево (`Expr`);
3. обчислення (`Evaluator`): дерево обходиться рекурсивно, з перевіркою області визначення функцій;
4. диференціювання (`Differentiator`) та спрощення (`Simplifier`): дерево перетворюється на нове дерево;
5. друк (`ExprPrinter`): дерево перетворюється назад на текст із мінімальною кількістю дужок.

Граматика виразів (від найнижчого пріоритету до найвищого):

```
expr    := term (('+' | '-') term)*
term    := unary (('*' | '/') unary | unary)*      -- друга альтернатива: неявне множення
unary   := ('-' | '+') unary | power
power   := postfix ('^' unary)?
postfix := primary '!'*
primary := число | x | π | e | функція primary | '(' expr ')'
```

Шар інтерфейсу (пакет `ui`) містить дві активності та допоміжні класи для виведення локалізованих повідомлень про помилки й вибору мови.

## Алгоритм символьного диференціювання

Похідна будується рекурсивно за структурою дерева виразу. Для кожного вузла застосовується відповідне правило:

```
(u ± v)′ = u′ ± v′
(u·v)′   = u′·v + u·v′
(u/v)′   = (u′·v − u·v′) / v²
(uⁿ)′    = n·uⁿ⁻¹·u′                      n не залежить від x
(aᵛ)′    = aᵛ·ln(a)·v′                    a не залежить від x
(uᵛ)′    = uᵛ·(v′·ln(u) + v·u′/u)         загальний випадок
f(u)′    = f′(u)·u′                       правило ланцюжка
```

Похідні елементарних функцій (sin, cos, tan, cot, asin, acos, atan, sinh, cosh, tanh, ln, log, √, exp, abs) задано таблично. Похідні вищих порядків отримуються послідовним застосуванням того самого перетворення.

Безпосередній результат диференціювання містить багато надлишкових членів. Наприклад, для x³ він має вигляд `3·x^(3−1)·1`. Тому після кожного кроку дерево спрощується: застосовуються правила переписування до досягнення нерухомої точки. Серед них згортання числових констант, вилучення нейтральних і поглинаючих елементів (u + 0, u·1, u·0, u¹, u⁰), зведення подібних доданків (2x + 3x = 5x), об'єднання степенів з однаковою основою (x·x² = x³) і скорочення спільних множників у дробах.

## Верифікація

Правильність ядра перевіряється двома незалежними способами.

Модульні тести (JUnit, каталог `app/src/test`) охоплюють синтаксичний аналіз, обчислення, обробку помилок і диференціювання. Для 20 функцій, трьох порядків похідної та чотирьох точок символьний результат порівнюється з оцінкою методом центральних скінченних різниць.

Додатково результати порівнюються з еталонною системою комп'ютерної алгебри SymPy (Python). Тест `DerivativeExportTest` експортує похідні, знайдені застосунком, у файл `app/build/derivative-check/derivatives.tsv`. Скрипт `tools/check_derivatives.py` знаходить ті самі похідні засобами SymPy і перевіряє їх символьну еквівалентність, тобто що `simplify(f_sympy − f_app) = 0`. Якщо SymPy не вдається звести різницю до нуля (наприклад, для abs(x)), скрипт порівнює значення в контрольних точках.

```bash
pip install -r tools/requirements.txt
./gradlew test
python tools/check_derivatives.py
python tools/check_derivatives.py --function "x^x" --order 2   # окрема функція
```

Скрипт є допоміжним інструментом перевірки і не входить до складу застосунку.

## Логування

Логування реалізовано за допомогою бібліотеки Timber. Налаштування виконується один раз під час запуску застосунку (клас `App`) і залежить від типу збірки. У debug-збірці використовується `DebugLogTree`: записуються повідомлення всіх рівнів, а тег містить назву файлу та номер рядка. У release-збірці використовується `ReleaseTree`: записуються лише повідомлення рівня INFO і вище, бо повідомлення нижчих рівнів можуть містити введені користувачем дані.

Рівні логування використовуються так: VERBOSE для натискань клавіш, DEBUG для подій життєвого циклу, INFO для результатів обчислень і зміни налаштувань, WARN для некоректного введення, ERROR для неочікуваних винятків. Повідомлення застосунку можна відфільтрувати в Logcat за тегом `SciCalc`.

## Інтернаціоналізація

Застосунок підтримує англійську (мова за замовчуванням), українську та німецьку мови. Рядки зберігаються в ресурсах `res/values`, `res/values-uk` та `res/values-de`. У програмному коді немає текстів, видимих користувачеві. Зокрема, ядро повідомляє про помилки кодами (`CalcError`), а відповідний текст обирається з ресурсів поточної мови. Використано параметризовані рядки та множинні форми (`plurals`), що враховують граматику кожної мови: в українській розрізняються форми one, few і many. Математичні позначення однакові для всіх мов, тому винесені в окремий файл із позначкою `translatable="false"`.

Мову можна змінити в самому застосунку через меню. Для цього використано API вибору мови для окремого застосунку (`AppCompatDelegate.setApplicationLocales`). На Android 13 і новіших версіях доступні мови оголошено у файлі `res/xml/locales_config.xml`, тому мову також можна вибрати в системних налаштуваннях.

## Збірка та запуск

Проєкт відкривається в Android Studio. Після синхронізації Gradle застосунок запускається на емуляторі або пристрої з Android 7.0 (API 24) чи новішою версією. Модульні тести запускаються командою `./gradlew test`.
